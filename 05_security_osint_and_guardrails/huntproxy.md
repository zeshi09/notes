## 🎯 1. В чем идея и почему Burp Suite устарел для агентов?

Традиционный инструментарий веб-пентестера (Burp Suite Pro, OWASP ZAP, Caido) проектировался десятилетия назад в расчете на **человека за монитором с мышкой в руке**:
1. **Тяжеловесность и UI-зависимость:** Запуск Burp Suite на удаленном VPS требует проброса X11/VNC либо нестабильных расширений; среда JVM потребляет гигабайты памяти.
2. **Костыли MCP-мостов:** Попытки подключить Burp к LLM через сторонние MCP-плагины часто приводят к рассинхронизации состояния: агент не «чувствует» браузер, сессии теряются при сбое соединения.
3. **Ручной труд:** Специалист по-прежнему вынужден вручную кликать по страницам, запускать плагины и копировать запросы.

**HuntProxy** создан с нуля на языке **Rust** как специализированный **Agent-First Security Workbench**. Он устраняет необходимость ручных манипуляций: агент получает готовый набор инструментов перехвата, исследования и фаззинга через единый протокол **MCP**, управляемый командами на обычном естественном языке.

## 🏗️ 2. Архитектура системы

```text
┌─────────────────────────────────────────────────────────────┐
│                       AI Agent Core                         │
│             (Claude Code / Codex / Antigravity)             │
└──────────────────────────────┬──────────────────────────────┘
                               │ Model Context Protocol (stdio / Docker)
┌──────────────────────────────▼──────────────────────────────┐
│                    HuntProxy Daemon (Rust)                  │
│                                                             │
│  ┌────────────────────────┐    ┌─────────────────────────┐  │
│  │   Capture Proxy Core   │    │  Managed Chromium Head  │  │
│  │  (Byte-exact HTTP/1-2) │    │ (Persistent Storage/DOM)│  │
│  └───────────┬────────────┘    └────────────┬────────────┘  │
│              │                              │               │
│  ┌───────────▼──────────────────────────────▼────────────┐  │
│  │ Project Store (~/.huntproxy/<project>)                 │  │
│  │ - Raw HTTP/S Traffic Log    - Live Sitemap Tree       │  │
│  │ - Session Cookies / Storage - Findings & Annotations  │  │
│  │ - WebSocket Frames Log      - Target Wordlists        │  │
│  └───────────────────────────────────────────────────────┘  │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ Engine Modules: Fuzzer (Sniper/Bomb) | Replay | Rules │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

### Ключевые компоненты:
* **Асинхронное ядро на Rust:** Сверхбыстрый перехват HTTP/1.1 и HTTP/2 с байтовой точностью (raw framing).
* **Управляемый Chromium:** Агент может отдавать команду на навигацию по сайту; куки, LocalStorage и состояние аутентификации сохраняются между запросами и рестартами демона.
* **Изолированное хранилище проектов:** Все дампы трафика, карты сайта, заметки и подтверждения находок упаковываются в проектную папку.

## 🧰 3. Функциональные возможности (Agent Hunting Loop)

HuntProxy реализует полноценный замкнутый цикл исследования: **Сбор контекста → Выдвижение гипотезы → Тестирование → Фиксация доказательств**.

### А. Сбор и сохранение контекста (Build & Preserve Context)
* **Projects:** Полная изоляция целей; несколько сессий агента могут работать с одним и тем же контекстом без потери истории.
* **Capture Proxy & Advanced Search:** Запись всего проходящего трафика с возможностью сложной булевой фильтрации (по хосту, методу, статусу, телам ответов, заголовкам и пользовательским меткам).
* **Автоматический Sitemap:** Превращение сырых запросов в иерархическое дерево маршрутов целевого приложения с параметрами, методами и типами контента.
* **JavaScript Endpoint Mining:** Автоматический парсинг загружаемых `.js` скриптов, извлечение скрытых API-эндпоинтов, параметров и генерация словарей под конкретную цель.
* **WebSockets:** Перехват активных WebSocket-сессий, протоколирование сообщений и возможность инъекции произвольных текстовых или бинарных фреймов в открытый сокет.

### Б. Тестирование гипотез (Test Hypotheses)
* **Replay / Raw Reply:** Повторная отправка модифицированных запросов с поддержкой точного побайтового контроля заголовков (критично для тестирования HTTP Request Smuggling и desync-атак).
* **Fuzzer:** Встроенный фаззер со стандартными режимами (*Sniper*, *Battering Ram*, *Pitchfork*, *Cluster Bomb*), поддержкой числовых диапазонов, regex-пэйлоадов и автоматической группировкой ответов по длине и статусу для выявления аномалий.
* **Request Rules:** Гибкие правила модификации заголовков и тел запросов на лету для браузера, прокси и фаззера.

### В. Фиксация доказательств (Evidence & Reporting)
* **Findings & Annotations:** Возможность привязать найденную уязвимость, текстовое описание и шаги воспроизведения прямо к конкретной сохраненной HTTP-транзакции.
* **Экспорт артефактов:** Мгновенная генерация воспроизводимых команд `curl` или готовых скриптов на Python для каждого запроса.

## ⚙️ 4. Конфигурация и подключение по MCP

### Запуск в среде разработчика
```bash
# 1. Установка через официальный скрипт
curl -fsSL https://raw.githubusercontent.com/BehiSecc/HuntProxy/master/install.sh | bash

# 2. Проверка окружения и Chromium
HuntProxy doctor
```

### Подключение к агенту (MCP JSON-конфиг)
```json
{
  "mcpServers": {
    "huntproxy": {
      "command": "/home/blackzeshi/.local/bin/HuntProxy",
      "args": ["mcp"]
    }
  }
}
```

### Запуск через Docker (для изолированных VPS)
```bash
docker run -d   --name huntproxy   --network host   --shm-size=1g   -v huntproxy-data:/data   huntproxy:local
```

## 💬 5. Пример работы агента через HuntProxy

Благодаря нативному MCP оператор может управлять аудитом естественным языком:

> **Промпт оператора:**  
> *«Подключись к HuntProxy MCP. Создай проект "FinTech-Audit" для https://target-app.internal. Запусти браузер, авторизуйся тестовым пользователем, составь sitemap и найди все эндпоинты, принимающие user_id в параметрах, чтобы проверить потенциальный IDOR.»*

**Что делает агент в фоне:**
1. Вызывает инструмент `huntproxy_create_project(name="FinTech-Audit")`.
2. Запускает Chromium через `huntproxy_browser_open(url="...")`, проходит форму логина и сохраняет куки в хранилище проекта.
3. Анализирует полученный Sitemap через `huntproxy_sitemap_get()`, фильтрует маршруты с параметром `user_id`.
4. Формирует запросы на фаззинг соседних идентификаторов через `huntproxy_fuzz(...)` и фиксирует аномалии в разделе Findings.

## 🎯 6. Место в стеке и польза для проекта `ai_pentester`

В рамках разработки собственного автономного пентестера (`ai_pentester`):
* `HuntProxy` закрывает ключевую брешь — отсутствие надежного, не зависящего от GUI веб-прокси с поддержкой MCP.
* Позволяет полностью отказаться от нестабильных связок с Burp Suite в headless-окружении.
* Легко разворачивается в Docker-контейнерах на удаленных серверах с минимальным потреблением ресурсов.
