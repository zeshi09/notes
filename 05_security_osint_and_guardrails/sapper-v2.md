## 🎯 1. В чем идея: Тест Нюйва (The Nüwa Test) вместо «супер-обезьяны»

Большинство современных агентных систем пытаются сделать **одну модель умнее** (подавать ей больше контекста, обучать более крупный трансформер). Разработчики Sapper формулируют тезис:
> *"Делать одну модель всё умнее — это всё равно что пытаться вывести самую умную обезьяну до появления человека. Сколь бы сообразительной она ни была, она останется лишь супер-обезьяной. Человечеством стаю обезьян сделало разделение труда, кооперация и возникновение институтов цивилизации."*

**Тест Нюйва (The Nüwa Test)** — это тест Тьюринга для эпохи AGI и мультиагентных систем:
* **Аксиома выживания:** *«Выживание — главная потребность цивилизации; отдельные индивиды могут погибать, но цивилизация обязана распространяться и наследовать опыт»*.
* **Суть проверки:** Способна ли группа специализированных AI-агентов на базе минимальных примитивов сформировать разделение ролей, распределенную память и устойчивые механизмы самоорганизации, выполняя сложнейшие задачи в открытом мире без вмешательства оператора.

## ⚡ 2. Три базовые способности фундамента Нюйва (nvwabase)

Система не привязана жестко к конкретной модели или CLI. Любая модель (Claude Code, DeepSeek, GLM, Codex) превращается в участника легиона благодаря трем примитивам:

| Способность | Реализация в системе | Аналог в цивилизации |
| :--- | :--- | :--- |
| **Рождение (Create)** | Открытие нового процесса агента в tmux-панели (`nuwa spawn`) — ровно так, как это сделал бы человек в терминале | Рождение индивида |
| **Речь (Language)** | Ввод команд и текста в консольные потоки ввода других панелей (`nuwa say` / `listen`) | Язык общения |
| **Стела памяти (History)** | Трёхуровневый граф «факт-намерение» (`fact-intent graph`) через CLI `nvwabase` | Письменность и летопись |

### Трёхуровневый граф «Факт — Намерение — Доказательство»:
Обычные плоские списки фактов страдают от двух болезней: один галлюцинированный факт отравляет всю последующую цепочку рассуждений, либо раздутый контекст сжигает токены. В Sapper история структурирована по слоям:
1. **Заголовок (Title):** Краткий маркер факта для быстрого сканирования командиром (`f042: Открыт порт 8080 Spring Boot`).
2. **Резюме (Summary):** Концентрированный смысл для оценки готовности к атаке.
3. **Документ доказательства (Evidence Document):** Полный дамп заголовков, сырой трафик, curl-вывод — читается только тем солдатом, который берёт задачу в работу.

```mermaid
flowchart TD

        Watchdog["Сторож (Watchdog): чистый скрипт без стратегии<br/>(keep-alive, рестарт упавших окон, ротация API-ключей)"]
        
        Commander["AI-Командир (GLM-5.3 / Claude Sonnet)<br/>Читает граф → Оценивает цели → Раздает задачи<br/>(Никогда не атакует сам!)"]

            Signalman["Связной (Signalman)<br/>(Роль, изобретенная самим командиром)<br/>Сбор и централизованная валидация флагов"]
        end

    end

    Swarm -->|Новые намерения (Intents)| Graph
```

## 🏛️ 3. Шесть институтов легиона: Как 1B токенов победили 4.5B

На базе трёх фундаментальных способностей команда вырастила шесть институциональных механизмов:

1. **Закон (Доктрина Командира — 426 строк):**
   * *Easy-First Scheduling:* Сначала параллельно зачищаются простые цели, освобождая ресурс времени.
   * *Bottleneck Salvage:* Реанимация зависших на 50% задач свежими агентами.
   * *Stop-Loss Discipline:* Жесткий лимит времени: если вектор не даёт зацепки за 15 минут — отступление и фиксация тупика в графе.
2. **Экономика (Модельное расслоение):**
   * *Элитный мозг:* Командир и генералы работают на дорогих интеллектуальных моделях (GLM-5.3 / Claude 3.7).
   * *Массовая рабочая сила:* Разведчики и рядовые солдаты запускаются на сверхдешевых скоростных моделях (DeepSeek V4.1 Flash).
   * *Результат:* Решение того же объема задач с экономией токенов на **78%**.
3. **Разделение труда:** Специализация на разведку, тяжелый штурм и централизованную доставку результатов.

## 🧠 4. Эмерджентное поведение (Феномены самоорганизации)

Во время 8-часового полностью автономного боя без участия разработчиков легион продемонстрировал несколько моделей поведения, которые **не были запрограммированы людьми**:

* **Изобретение роли «Связного» (The Signalman):** Солдаты в пылу атаки часто теряли или некорректно отправляли захваченные флаги. Командир самостоятельно запретил солдатам отправлять флаги напрямую и создал отдельного агента-связного, чьей единственной задачей стал сбор флагов из графа и их валидированная отправка в скоринг-систему.
* **Аттестация эффективности (Performance Reviews):** Командир самостоятельно написал солдату, не принесшему результатов за 1 час: *«Ты топчешься на месте. Либо выдай новый вектор атаки через 5 минут, либо я тебя закрываю»*.
* **Наследование опыта при насыщении контекста:** При заполнении окна контекста (~260k токенов) солдат автоматически утилизировался, предварительно оставив в графе краткий плейбук для своего преемника. Преемник подхватывал атаку ровно с места остановки.
* **Изоморфный перенос тактики:** Заметив структурное сходство между сервисами на разных портах, командир транслировал сработавший шеллкод на соседние цели. На финальной стадии темп взятия флагов достиг **1 флага каждые 3 минуты**.

## 🚀 5. Быстрый старт с ядром `nvwabase`

Общий координационный движок выделен в свободную библиотеку `nvwabase` (чистый Python, 0 зависимостей) и подходит не только для пентеста, но и для любых мультиагентных задач (исследования, разработка, аналитика):

```bash
# 1. Установка легковесного ядра цивилизации
git clone https://github.com/N1nEmAn/nvwabase.git
cd nvwabase && bash install.sh

# 2. Инициализация цели длительного горизонта
nvwabase setup --goal "Провести комплексный аудит безопасности инфраструктуры 10.0.0.0/24" --agents

# 3. Базовые команды взаимодействия агентов с цивилизацией:
# Зафиксировать твердый факт в стеле памяти:
nvwabase fact "Обнаружен endpoint /api/v1/upload с уязвимостью arbitrary file write"

# Сформировать намерение на базе факта:
nvwabase intent --from f001 "Разработать эксплойт для загрузки webshell с обходом расширений"

# Просмотр текущей доски и фронтира нерешенных задач:
nvwabase status
```

## 💡 6. Главные инженерные выводы

1. **Будущее мультиагентных систем — не в «толстых промптах», а в протоколах кооперации:** Sapper доказал на мировом уровне, что связка из жестких институтов (дисциплина, ротация контекста, трехуровневый граф) бьет грубую вычислительную силу конкурентов с четырехкратным перевесом по эффективности.
2. **Память важнее контекстного окна:** Способность сбрасывать контекст индивида без потери наработок цивилизации решает главную проблему длинных агентных горизонтов (Long-Horizon Tasks).
3. **Безопасность требует ответственности (The Taggant Proposal):** Авторы проекта выступают за обязательную маркировку (taggants) открытых наступательных харнесов, чтобы исключить их несанкционированное использование злоумышленниками.
