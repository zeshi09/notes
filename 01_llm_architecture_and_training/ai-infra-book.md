## 🎯 1. В чем метод книги? «От аппаратных ограничений — к системному дизайну»

Большинство инженеров и исследователей рассуждают об AI-системах на абстрактном уровне: *«Возьмем 8x H100, запустим vLLM с тензорным параллелизмом (TP=8) и получим скорость N токенов/сек»*. Однако на практике системы внезапно упираются в «необъяснимые» просадки производительности:
* Считали только чтение весов модели, но **забыли про размер и пропускную способность KV Cache**.
* Оценивали скорость по пиковым TFLOPS тензорных ядер, но **не проверили, способна ли пропускная способность памяти (HBM Memory Bandwidth) подавать данные с нужной частотой**.
* Разделили модель на несколько карт, но **не учли задержки и накладные расходы межкарточной коммуникации (All-Reduce over NVLink/PCIe)**.

Метод Ли Боцзе — **количественный вывод архитектуры систем из физических ограничений первого порядка (Roofline Model, физика кремния, топология сетей)**.

> **Главный лейтмотив AI-инфраструктуры — Перемещение Данных (Data Movement).**  
> Книга на протяжении всех 12 глав задает инженеру 5 бескомпромиссных вопросов:
> 1. **Что** перемещается? (Веса, KV-кэш, активации, градиенты, состояния оптимизатора).
> 2. **Сколько** байт перемещается? (Точный количественный расчет формулой).
> 3. **Сколько раз** перемещается? (Фьюзинг операторов, кэширование, повторные вычисления).
> 4. **Через какие шины** проходит путь? (SRAM $\leftrightarrow$ HBM $\leftrightarrow$ NVLink $\leftrightarrow$ PCIe $\leftrightarrow$ RDMA/RoCEv2).
> 5. **Кто должен ждать** завершения передачи? (Синхронные барьеры, перекрытие вычислений и связи).

## 🧮 3. Комплект расчетных инструментов без GPU (`calculations/calc.py`)

Уникальное достоинство репозитория — набор утилит для количественного расчета характеристик моделей на чистом Python без необходимости запускать тяжелые GPU:
```bash
git clone https://github.com/bojieli/ai-infra-book.git
cd ai-infra-book

# Просмотр базы профилей поддерживаемых моделей (Qwen, Llama, DeepSeek, Mistral)
python3 calculations/calc.py models

# Расчет послойных потребностей в памяти и FLOPS для Qwen-8B при Prefill в 8192 токена
python3 calculations/calc.py forward --model qwen3-8b --tokens 8192 --format md
```
Утилита генерирует строгий отчет с распределением нагрузки по операторам (GEMM, Softmax, LayerNorm, RMSNorm, RoPE), показывая, упирается ли операция в память (Memory-bound) или в вычисления (Compute-bound).
