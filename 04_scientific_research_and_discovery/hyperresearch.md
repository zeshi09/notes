## 🎯 1. В чем проблема обычного Deep Research и почему Hyperresearch?

Подавляющее большинство существующих Deep Research систем (OpenAI Deep Research, Gemini Deep Research, Perplexity) работают по принципу **одноразового запроса (One-Shot Burner)**:
1. Агент делает несколько веб-поисков, читает поверхностные выжимки и генерирует отчет.
2. **Все прочитанные источники и доказательства выбрасываются.** Следующая сессия начинается с чистого листа, тратя те же доллары и токены на поиск того, что уже однажды было найдено.
3. **Пейволлы и симуляция чтения:** Закрытые статьи цитируются по абстракту на 1500 символов, словно агент прочитал работу целиком.
4. **Синдикация выдается за консенсус:** Если 5 СМИ перепечатали один пресс-релиз, наивный агент считает это пятью независимыми подтверждениями.
5. **Галлюцинации цитат:** Модели приписывают источникам выводы, которых там нет, или ссылаются на отозванные статьи (retractions).

**Hyperresearch** решает эти проблемы архитектурно: он сочетает **16-шаговый конвейер состязательного исследования** и **персистентное хранилище (Compounding Vault)**, где каждая прочитанная статья навсегда сохраняется, индексируется и переиспользуется в будущих исследованиях.

## 🏛️ 2. Архитектура хранилища: «Markdown — истина, SQLite — кэш»

```text
research/
├── notes/                   # Полнотекстовые Markdown-файлы с YAML Frontmatter
│   ├── note-01.md           # Первоисточник, аннотация, теги, provenance
│   └── note-02.md
├── raw/                     # Оригинальные выкачанные PDF и HTML файлы
│   └── note-01.pdf
├── runs/                    # Журналы прогонов, манифесты и черновики
│   └── <vault_tag>/query.md
└── vault.db                 # SQLite + FTS5 полнотекстовый индекс (кэш)
```

* **Полная независимость от вендора:** Если удалить `vault.db`, команда `hyperresearch sync` мгновенно пересоберет индекс из каталога Markdown-файлов. Все заметки открываются в Obsidian, Logseq или обычном VS Code.
* **Единый клиент к 8 научным базам:** Одной командой `hpr scholar search` опрашивает OpenAlex, Crossref, CORE, DOAB, ClinicalTrials.gov, SEC EDGAR и FRED, дедуплицируя результаты по DOI и названию.
* **Честный обход пейволлов:** При встрече с закрытой статьей Hyperresearch автоматически запрашивает легальные Open Access копии через Unpaywall, Europe PMC и CORE, скачивая полный PDF и извлекая текст через `pymupdf`. Каждая подмена абстракта на полный текст явно фиксируется во фронтматтере.
* **Происхождение данных (Provenance Breadcrumbs):** Каждый источник снабжен ссылкой `--suggested-by`, связывающей его с родительской ссылкой, создавая проверяемое корневое дерево цитирования.

## 🛡️ 4. Два краеугольных принципа надежности

1. **Точечный патчинг вместо полной регенерации (Patch, Never Regenerate):**  
   После того как синтезатор собрал черновик, агентам-редакторам (`patcher` и `polish`) на уровне системных прав Claude Code **физически заблокирован инструмент Write** — они имеют доступ только к `[Read, Edit]`. Правки вносятся исключительно хирургическими диффами (Edit hunks). Модель не может случайно стереть важный раздел или переписать отчет своими словами.
2. **Канонический запрос священен (Canonical Query is Gospel):**  
   Исходный промпт пользователя неизменно сохраняется в `research/runs/<tag>/query.md`. Каждый субагент перечитывает оригинальный текст, что гарантирует точное следование ТЗ без дрейфа внимания.

## ⚡ 5. Масштабирование: Tiers и Gears

Режим исследования масштабируется под задачу:

| Уровень (Tier) | Что запускается | Время работы | Объем корпуса |
| :--- | :--- | :--- | :--- |
| **`light`** | Быстрый фактчекинг и обзоры (шаги 1 $ightarrow$ 2 $ightarrow$ 10 $ightarrow$ 15 $ightarrow$ 16) | ~30–40 мин | 20–35 источников |
| **`full` (по умолчанию)** | Глубокий состязательный анализ с 4 критиками и аутентификацией цитат | ~1.5–2.5 часа | 55–130 источников |
| **`dissertation`** | Монументальные исследования на 4–10 глав (25k–80k слов) | ~4–8 часов | 300–450 источников |

## 🔌 6. Использование вне Claude Code: MCP и Web UI

Hyperresearch — это не только скилл, но и полноценная исследовательская станция:

* **Встроенный MCP Server:**  
  Команда `hyperresearch mcp` поднимает сервер со стандартным протоколом (stdio) с **13 инструментами** (`search_notes`, `read_note`, `get_backlinks`, `get_hubs`, `lint_vault`, `fetch_url` и др.). Хранилище доступно из Cursor, Claude Desktop или Antigravity.
* **Встроенный Web UI:**  
  Команда `hyperresearch serve --open` запускает локальный веб-сервер на порту 8080: поиск по базе, фильтрация по тегам и интерактивный граф связей без внешних JS-зависимостей.

## 🚀 7. Установка и запуск

```bash
# 1. Установка пакета (Python 3.11–3.13)
pip install hyperresearch && hyperresearch install

# 2. Опционально: поддержка MCP
pip install "hyperresearch[mcp]"

# 3. Запуск глубокого исследования в Claude Code
/hyperresearch "Сравнительный анализ архитектур TCB и Reference Monitor в агентных рантаймах"

# 4. Полнотекстовый поиск по накопленной базе знаний
hyperresearch search "Reference Monitor" -j

# 5. Запуск интерактивного графа в браузере
hyperresearch serve --open
```
