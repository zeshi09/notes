## 🎯 1. В чем главная философия книги?

### «Сначала практика, потом название»
В индустрии искусственного интеллекта новые термины появляются каждую неделю: *ReAct, Reflection, Harness Engineering, Tool RAG, Context Compaction, Agent Society*. Автор подчеркивает ключевое правило корпоративной и исследовательской разработки:
> **Если вы каждый раз ждете, пока в индустрии станет популярным какой-нибудь термин, прежде чем начать применять его на практике — вы уже безнадежно опоздали.** К моменту популяризации термина ведущие лаборатории уже прошли эту проблему насквозь.

### Фундаментальная формула агента
Вся книга выстроена вокруг лаконичной, но исчерпывающей формулы:

$$\mathbf{Agent} = \mathbf{LLM} + \mathbf{Context} + \mathbf{Tools}$$

![Агент = Мозг + Глаза + Руки-ноги](https://raw.githubusercontent.com/bojieli/ai-agent-book/main/book-ru/images/fig0-1.svg)

1. **Мозг (LLM / Policy):** Процессор рассуждений, отвечающий за планирование, вывод и принятие решений.
2. **Глаза (Контекст / Observation Space):** Все, что модель способна воспринять (системные промпты, история диалога, результаты вызовов инструментов, извлеченные знания, определения доступных функций).
3. **Руки и ноги (Инструменты / Action Space):** Все, что агент может физически совершить во внешнем мире (API, shell, MCP, модификация кода, клики по GUI).

Ни один из трех компонентов нельзя выбросить. При этом **Harness-инженерия (среда исполнения, протоколы взаимодействия, контуры верификации)** — это то, где формируется настоящее долгосрочное конкурентное преимущество, переживающее поколения базовых моделей.

## 🔬 3. Детальный разбор ключевых глав

### 🧠 Глава 2: Инженерия контекста и физика KV Cache
Контекст — главное физическое бутылочное горлышко агента. Глава не просто учит писать промпты, а раскрывает аппаратную природу контекста:
* **Механика KV Cache и Prefix Caching:** Как правильное структурирование неизменяемых префиксов промпта (манифестов инструментов, неизменных правил) позволяет повторно использовать кэш внимания GPU, снижая задержку Time-To-First-Token (TTFT) и затраты в разы.
* **Agent Skills:** Паттерн изоляции навыков в файлы `SKILL.md` с динамической загрузкой по триггерам вместо раздувания глобального системного промпта.
* **Сжатие контекста (Context Compression):** Алгоритмы иерархической суммаризации, вырезание промежуточных шумов и удержание критических якорей состояния.

### 🛠️ Глава 4: Инструменты и Model Context Protocol (MCP)
* **Стандартизация интерфейсов:** Переход от закрытых самописных плагинов к протоколу **MCP** (Model Context Protocol).
* **Три типа инструментов:** Инструменты *восприятия* (Perception — чтение веб-страниц, логов), *исполнения* (Execution — компиляторы, bash, базы данных) и *сотрудничества* (Collaboration — общение с пользователем или другими агентами).
* **Активное обнаружение (Tool RAG):** Когда у системы тысячи доступных инструментов, подавать их все в контекст нельзя. Используется динамический двухэтапный поиск: по запросу агента отбираются топ-k релевантных инструментов.

### 💻 Глава 5: Кодинг-агент и промышленная генерация кода
Код — это высшая форма действия, поскольку код сам может порождать новые программы и инструменты:
* **Архитектура промышленного агента:** Полная декомпозиция движка, аналогичного Claude Code / Devin / OpenCode.
* **AST-анализ и Git-интеграция:** Агент работает не с абстрактным текстом, а с синтаксическим деревом (Tree-sitter) и транзакционными коммитами.
* **Песочницы и строгий контур верификации:** Обязательный запуск линтеров, компиляторов и unit-тестов перед фиксацией изменений (защита от синдрома «преждевременной победы»).

### 🎯 Глава 7: Научная оценка агентов (Agent Evals)
Фундаментальный постулат автора: **«Без строгой оценки невозможно отличить качественное архитектурное улучшение от случайного статистического шума»**.
* **Среды оценки:** Использование детерминированных тестовых сред (Tau2-bench, HumanEval, SWE-bench).
* **Калиброванный LLM-as-a-Judge:** Принципы составления однозначных рубрик (Rubrics), минимизация предвзятости позиции и длины ответа.
* **Статистическая значимость:** Анализ доверительных интервалов и расчет необходимого количества прогонов для верификации гипотез.

### 🏋️ Глава 8: Постобучение моделей (Post-Training: SFT vs RL)
* **«SFT запоминает, RL обобщает»:** Почему дообучение с учителем (SFT) хорошо подходит для фиксации синтаксиса вызова инструментов, но бесполезно для сложных многошаговых рассуждений, где требуется Reinforcement Learning (PPO, GRPO).
* **Дизайн наград (Reward Design):** Принцип «вознаграждать результат, ограничивать процесс» — модель получает максимальную награду за успешное решение задачи, но штрафуется за нарушение политик безопасности и неэффективный расход шагов.
* **CoT-дистилляция:** Перенос способностей длинных рассуждений из тяжелых моделей в компактные локальные агенты.

### 🔄 Глава 9: Непрерывная эволюция (Continuous Evolution)
Как превратить эксплуатационный опыт работающего агента в улучшения его следующей версии:
* **Траекторные верификаторы:** Автоматический анализ логов реальных сессий и классификация ошибок.
* **Четыре носителя обновлений:**
  1. *Документы знаний (Knowledge):* Добавление фактов в RAG-базу.
  2. *Инструкции (Prompt & Skills):* Тюнинг системных промптов и добавление новых `SKILL.md`.
  3. *Программы (Harness & Code):* Модификация связующего кода раннера и инструментов.
  4. *Параметры модели (Weights):* Запуск циклов дообучения весов на отобранных идеальных траекториях.

### 🤝 Глава 10: Многоагентные системы (Multi-Agent Collaboration)
* **Классификационная матрица 2×3:** Общий vs изолированный контекст $	imes$ равноправная сеть / иерархия с диспетчером / децентрализованный рынок.
* **Шесть типичных режимов отказа:** Каскадные галлюцинации, бесконечные циклы перекладывания ответственности, взаимная блокировка (deadlock), деградация согласованности контекста, расхождение протоколов и потеря глобальной цели.
* **Протоколы Agent-to-Agent (A2A):** Меж-агентные спецификации передачи состояния и делегирования задач.

### Быстрый запуск воспроизводимого окружения через `uv`
Проект стандартизирован на современный пакетный менеджер **`uv`**:
```bash
# 1. Клонирование репозитория
git clone https://github.com/bojieli/ai-agent-book.git
cd ai-agent-book

# 2. Воспроизводимая синхронизация окружения для конкретной главы (например, главы 1)
uv sync --locked --extra ch1

# 3. Запуск эталонного эксперимента по работе с контекстом
uv run python chapter1/context/main.py

# 4. Запуск экспериментов других глав:
uv sync --locked --extra ch4  # Инструменты и MCP
uv run python chapter4/execution-tools/main.py

uv sync --locked --extra ch5  # Полноценный кодинг-агент
uv run python chapter5/coding-agent/main.py
```
