## 🎯 1. В чем проблема ревью универсальными AI-агентами?

Когда разработчики пытаются использовать универсальные кодинг-агенты (Claude Code, Cursor) с текстовыми промптами или простыми Skills для код-ревью крупных изменений, они неизбежно сталкиваются с тремя системными дефектами:
1. **Неполное покрытие («Срезание углов» / Cutting Corners):** На больших Pull Request (20+ файлов) агент начинает выборочно читать только часть файлов, пропуская критические изменения в смежных модулях.
2. **Дрейф позиционирования (Position Drift):** LLM часто ошибается в номерах строк, комментирует соседние участки кода или путает контекст добавленных и удаленных строк в диффе.
3. **Нестабильное качество и шум:** Чисто текстовые промпты подвержены случайным колебаниям. Из-за этого количество ложных срабатываний (False Positives) зашкаливает, и инженеры перестают доверять ревью.

**Причина:** Чисто языковая архитектура не имеет жестких детерминированных ограничений на процесс обхода и валидации кода.

## 🏗️ 2. Архитектурная парадигма: Deterministic Engineering × Agent Hybrid

Open Code Review решает эту проблему за счет четкого разделения труда между **жесткой программной логикой (Hard Constraints)** и **динамическим интеллектом модели (Agent)**:

```text
┌────────────────────────────────────────────────────────────────────────┐
│                     Pull Request / Git Diff Input                      │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│              DETERMINISTIC ENGINEERING (Hard Constraints)              │
│                                                                        │
│  ┌─────────────────────────┐         ┌──────────────────────────────┐  │
│  │ AST & Diff Parser       │         │ Smart File Bundler           │  │
│  │ (Точный отбор файлов)   │────────►│ (Группировка связанных узлов)│  │
│  └─────────────────────────┘         └──────────────┬───────────────┘  │
│                                                     │                  │
│  ┌─────────────────────────┐                        ▼                  │
│  │ Rule Matcher            │         ┌──────────────────────────────┐  │
│  │ (NPE, XSS, SQLi, Concur)│────────►│ File Bundles (Sub-Agents)   │  │
│  └─────────────────────────┘         └──────────────┬───────────────┘  │
└─────────────────────────────────────────────────────┼──────────────────┘
                                                      │ Isolated Context
┌─────────────────────────────────────────────────────▼──────────────────┐
│                   LLM AGENT (Dynamic Decision Making)                  │
│                                                                        │
│  • Scenario-Tuned Prompts: узкий фокус внимания без лишних токенов    │
│  • Special Toolset: точечный поиск по AST, чтение связей и сигнатур   │
│  • Independent Reflection & Position Verifier (Проверка строк)        │
└─────────────────────────────────────┬──────────────────────────────────┘
                                      │
┌─────────────────────────────────────▼──────────────────────────────────┐
│          Structured Line-Level Review Comments (SARIF / PR)            │
└────────────────────────────────────────────────────────────────────────┘
```

### А. Детерминированная часть (что гарантирует софт)
* **Точный отбор файлов:** Инженерная логика на Go строго определяет, какие файлы обязаны пройти аудит, а какие являются автогенерированными или бинарными.
* **Умное бандлирование (Smart File Bundling):** Взаимосвязанные файлы (например, интерфейс и его реализация или парные локали `messages_en` / `messages_ru`) объединяются в единый аналитический блок. Каждый блок обрабатывается изолированным субагентом с чистым контекстом, что позволяет параллельно и без переполнения контекста ревьюить изменения любого масштаба.
* **Шаблонизированный матчинг правил:** Правила для конкретных языков (Go, Java, Python, TS, Rust) подтягиваются детерминированным движком, а не раздутым системным промптом.
* **Внешний модуль позиционирования и рефлексии:** Отдельный верификатор проверяет, что сгенерированное замечание строго указывает на корректную строку файла и не является галлюцинацией.

### Б. Агентная часть (где работает нейросеть)
* Модель не тратит внимание на рутинную фильтрацию, а занимается семантическим анализом логики, гонок потоков (race conditions) и неочевидных граничных случаев.
* Специализированный набор инструментов: агент умеет запросить определение функции из другой части проекта, проверить использование переменной или просмотреть историю коммитов.

## 📊 3. Бенчмарк AACR-Bench: 1/9 токенов при рекордной точности

Alibaba опубликовала открытый датасет **AACR-Bench** на Hugging Face (50 популярных open-source репозиториев, 200 реальных PR на 10 языках программирования, 1505 эталонных дефектов, размеченных 80+ сеньор-инженерами).

| Параметр | Обычный универсальный агент (Claude Code) | Open Code Review (Alibaba) | Разница / Выгода |
| :--- | :---: | :---: | :---: |
| **Precision (Точность)** | ~42.3% | **76.8%** | **+34.5%** (минимум ложного шума) |
| **F1 Score** | ~51.2% | **68.4%** | **Выше качество найденных багов** |
| **Расход токенов на PR** | ~185,000 токенов | **~21,000 токенов** | **Расход ниже в ~9 раз!** |
| **Время выполнения** | 4 мин 12 сек | **48 секунд** | **Ускорение в 5 раз** |

> Примечание: Умыш сознательно понижен Recall в пользу экстремально высокого Precision. Для разработчиков критически важно, чтобы AI-ассистент не спамил бессмысленными придирками к стилю, а указывал на реальные сбои.

## 🚀 4. Установка и запуск

### Быстрый старт через CLI
```bash
# 1. Глобальная установка утилиты
npm install -g @alibaba-group/open-code-review

# 2. Настройка провайдера моделей (OpenAI, Anthropic, DeepSeek, локальный vLLM)
export OCR_API_KEY="sk-..."
export OCR_BASE_URL="https://api.deepseek.com/v1"
export OCR_MODEL="deepseek-chat"

# 3. Запуск ревью текущего незакоммиченного дифа
ocr review

# 4. Ревью конкретного коммита или ветки относительно main
ocr review --target main

# 5. Полный аудит всей папки или репозитория без diff (режим аудита)
ocr scan ./src
```

### Интеграция в GitHub Actions / GitLab CI
```yaml
name: Open Code Review
on: [pull_request]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - name: Run OCR
        uses: alibaba/open-code-review-action@v1
        with:
          api-key: ${{ secrets.DEEPSEEK_API_KEY }}
          model: deepseek-chat
          github-token: ${{ secrets.GITHUB_TOKEN }}
```
