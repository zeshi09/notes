## 🎯 1. Введение: Главная идея Harness Engineering

### Проблема «голых» AI-агентов
Современные большие языковые модели (LLM) обладают огромным объемом знаний и логических способностей, однако при автономной работе в реальных кодовых базах они регулярно терпят неудачу:
1. **Преждевременное объявление победы (Premature Victory):** Агент пишет код и заявляет *«Все готово и работает идеально»*, не запустив линтер, компилятор или тесты.
2. **Потеря контекста и деградация в длинных сессиях:** Модель забывает начальные цели, зацикливается или переписывает уже работающие модули.
3. **Распыление скоупа (Overreach & Under-finish):** Агент берется за 10 задач одновременно, вносит хаотичные диффы и оставляет кодовую базу в сломанном состоянии.

---

### Архитектурный сдвиг: Model vs. Harness

```text
┌────────────────────────────────────────────────────────────────────────┐
│                              AGENT HARNESS                             │
│                                                                        │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │                         MODEL (LLM)                            │   │
│   │   «Процессор рассуждений»: генерация диффов, чтение кода,      │   │
│   │   принятие локальных решений.                                  │   │
│   └──────────────────────────────┬─────────────────────────────────┘   │
│                                  │                                     │
│   ЖИЗНЕННЫЙ ЦИКЛ И ПРАВИЛА (Governed by Harness):                      │
│   1. System of Record (Git, state files, feature_list.json)            │
│   2. Строгие фазы: Init -> Plan -> Edit -> Test -> Verify -> Commit   │
│   3. Объективная верификация (linters, typecheck, unit/e2e tests)      │
│   4. Чистое состояние при завершении сессии (clean session handoff)    │
└────────────────────────────────────────────────────────────────────────┘
```

> **Ключевой вывод курса:**  
> Качество и стабильность автономной работы агента на **80% зависят от конструкции среды (Harness)** и лишь на **20% — от «ума» конкретной модели**.

## 📚 2. Структура учебного курса (14 Лекций)

### Модуль 1: Фундамент и анатомия сбоев
* **Lecture 01: Why capable agents still fail**  
  Разбор реальных сценариев сбоя передовых моделей на реальном коде. Анализ «слепых зон» и причин деградации рассуждений.
* **Lecture 02: What a harness actually is**  
  Четкое разграничение ответственности: что решает модель, а чем жестко управляет среда (Harness).
* **Lecture 03: Why the repository must become the system of record**  
  Память агента не должна зависеть от скрытого контекстного окна LLM. Единственный источник истины — это файлы репозитория (`progress.md`, `feature_list.json`, коммиты Git).

### Модуль 2: Управление контекстом и инструкциями
* **Lecture 04: Why one giant instruction file fails**  
  Антипаттерн монолитного `SYSTEM_PROMPT.md` на тысячи строк. Разделение инструкций на модульные, контекстно-загружаемые скиллы и правила.
* **Lecture 05: Why long-running tasks lose continuity**  
  Организация бесшовной передачи состояния между сессиями (`session-handoff`) без потери нити разработки.
* **Lecture 06: Why initialization needs its own phase**  
  Почему фаза первичного сканирования и анализа кодовой базы должна быть строго изолирована от фазы модификации кода.

### Модуль 3: Верификация и контроль качества
* **Lecture 07: Why agents overreach and under-finish**  
  Ограничение радиуса изменений за одну итерацию. Принцип атомарных инкрементальных правок.
* **Lecture 08: Why feature lists are harness primitives**  
  Использование структурированного списка фич (`feature_list.json`) как фундаментального примитива управления прогрессом.
* **Lecture 09: Why agents declare victory too early**  
  Замена субъективной оценки модели (*«looks good to me»*) на обязательную программную верификацию.
* **Lecture 10: Why end-to-end testing changes results**  
  Встраивание реальных прогонов E2E-тестов, юнит-тестов и тайпчека в цикл обратной связи агента.

### Модуль 4: Наблюдаемость и сложные архитектуры
* **Lecture 11: Why observability belongs inside the harness**  
  Сбор телеметрии, логов вызовов инструментов и аудит промежуточных шагов рассуждения.
* **Lecture 12: Why every session must leave a clean state**  
  Правила завершения сессии: откат сломанных временных файлов, запись статуса и обеспечение воспроизводимого перезапуска.
* **Lecture 13: Loop Engineering**  
  Проектирование и тонкая настройка автономных агентных циклов (ReAct, Plan-and-Execute, Reflection).
* **Lecture 14: Graph Engineering**  
  Оркестрация сложных мульти-агентных графов зависимостей и параллельного распределения задач.

## 🛠 3. Практические проекты (8 Hands-on Projects)

Каждый проект в курсе сравнивает результат выполнения задачи **«голым» агентом (Baseline)** против **агента в среде Harness**:

1. **Project 01: Baseline vs Minimal Harness** — демонстрация разницы при добавлении базового каркаса верификации.
2. **Project 02: Agent-Readable Workspace** — подготовка структуры проекта, оптимизированной под чтение AI-агентом.
3. **Project 03: Multi-Session Continuity** — решение задачи в 5 последовательных независимых сессий с передачей контекста.
4. **Project 04: Incremental Indexing** — инкрементальное индексирование архитектуры крупной кодовой базы.
5. **Project 05: Grounded QA Verification** — организация жесткого контура верификации фактов и работы функционала.
6. **Project 06: Runtime Observability and Debugging** — внедрение трейсинга и инструментов отладки агента в реальном времени.
7. **Project 07: Loop Engineering (First Loop)** — создание собственного агентного цикла на TypeScript с нуля.
8. **Project 08: Graph Engineering (First Graph)** — создание ориентированного графа взаимодействующих специализированных субагентов.

## 🧰 4. Встроенные утилиты репозитория

### 1. `audit-harness.sh` — Скрипт аудита репозитория
Проверяет любую кодовую базу на соответствие 5 ключевым подсистемам Harness (L03–L12). Работает на чистом Bash без внешних зависимостей.

```bash
# Запуск напрямую через curl
curl -fsSL https://raw.githubusercontent.com/walkinglabs/learn-harness-engineering/main/tools/audit-harness.sh | bash -s -- /путь/к/проекту

# Или локально из склонированного репозитория
bash tools/audit-harness.sh /путь/к/проекту
```

### 2. `skills/harness-creator` — Генератор Harness для AI-агентов
Готовый скилл, который можно подключить в Claude Code / Codex / Antigravity для автоматической генерации конфигурационных файлов, чеклистов и тестов под новый проект.

## 📋 5. Чек-лист внедрения Harness в свой проект

Чтобы превратить обычный репозиторий в **Agent-First Workspace**, необходимо внедрить следующие артефакты:

| Файл / Компонент | Назначение |
| :--- | :--- |
| `AGENTS.md` / `CLAUDE.md` | Лаконичные высокоуровневые правила, стек, команды сборки, запуска тестов и линтеров. |
| `feature_list.json` | Машиночитаемый список требований и фич со статусами (`pending`, `in_progress`, `verified`). |
| `progress.md` | Журнал текущей сессии: что сделано, какие ошибки встречены, следующий шаг для возобновления. |
| `scripts/verify.sh` | Единый скрипт быстрой проверки (`lint + typecheck + test`), возвращающий `exit 0` только при 100% успехе. |
| `.agents/skills/` | Модульные инструкции под узкие задачи (рефакторинг, миграции БД, генерация тестов). |

## 🚀 6. Как запустить учебник локально

Репозиторий оформлен в виде интерактивного портала документации на **VitePress**:

```bash
# 1. Клонирование репозитория
git clone https://github.com/walkinglabs/learn-harness-engineering.git
cd learn-harness-engineering

# 2. Установка зависимостей
npm install

# 3. Запуск локального сервера документации
npm run docs:dev
```

После этого перейдите по адресу `http://localhost:5173` в браузере для чтения лекций и просмотра интерактивных диаграмм.
