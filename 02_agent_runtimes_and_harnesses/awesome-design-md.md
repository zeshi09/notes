## 🎯 1. В чем идея DESIGN.md?

Главная проблема AI-агентов при генерации веб-интерфейсов — **визуальная халтура («AI Slop»)**: случайные цвета, разнобой в скруглениях, уродливые тени и отсутствие общего стиля.

Концепция **`DESIGN.md`** решает эту проблему элегантно:
* В корень вашего проекта кладется один файл `DESIGN.md`, описывающий строгие правила визуального языка (токены, цвета, отступы, типографику, анимации и состояния компонентов).
* Когда вы просите агента: *«Сделай страницу настроек»*, модель читает `DESIGN.md` и генерирует код, **на 100% соответствующий фирменному стилю**.

```text
┌────────────────────────┐
│   DESIGN.md в проекте  │ ──► [ Цвета, токены, сетка, скругления, шрифты, компоненты ]
└───────────┬────────────┘
            │
            ▼
┌────────────────────────┐
│  AI Кодинг-Агент       │ ──► Читает спецификацию как системное правило
│ (Claude Code / Cursor) │
└───────────┬────────────┘
            │
            ▼
┌────────────────────────┐
│  Идеальный брендовый   │ ──► Чистый React/Tailwind без дефектов и визуального шума
│  интерфейс из коробки  │
└────────────────────────┘
```

## 🚀 3. Как использовать на практике?

1. Скопируйте нужный файл спецификации в корень своего репозитория:
   ```bash
   cp design-systems/linear.DESIGN.md ./DESIGN.md
   ```
2. Отдайте команду своему AI-агенту (в Claude Code, Cursor или Antigravity):
   > *«Изучи DESIGN.md в корне проекта и сверстай дашборд аналитики на React + Tailwind, строго соблюдая цветовую палитру и правила компонентов из спецификации».*
