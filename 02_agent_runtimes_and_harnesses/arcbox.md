## 🎯 1. Зачем нужен ArcBox?

Главная проблема запуска автономных кодинг-агентов (Claude Code, Codex, Antigravity, OpenCode) — **безопасность и скорость изоляции**:
* Если дать агенту доступ к основной системе, он может случайно выполнить `rm -rf` или перезаписать системные файлы.
* Традиционный Docker Desktop или тяжелые виртуальные машины запускаются по несколько секунд, потребляют гигабайты RAM и создают большой оверхед.

**ArcBox** — это открытый сверхбыстрый контейнерный и VM-рантайм, написанный с нуля на **Rust**, оптимизированный под мгновенный запуск одноразовых песочниц (*Agent Sandboxes*):

```text
┌────────────────────────────────────────────────────────────────────────┐
│                              ARCBOX RUNTIME                            │
│                                                                        │
│   • Холодный старт микро-VM: <100 мс (в 10-20 раз быстрее Docker)      │
│   • Полная изоляция: собственное ядро Linux, память, ФС и сеть         │
│   • Потребление RAM в простое: <30 МБ                                  │
│   • 100% OCI-совместимость (Drop-in замена Docker CLI)                 │
│   • Нативная интеграция с агентными рантаймами через сокет и API       │
└────────────────────────────────────────────────────────────────────────┘
```

---

## 🛠 2. Ключевые возможности

1. **Agent Sandboxing:** Создание изолированной среды для тестирования кода агента за миллисекунды с мгновенным сбросом состояния (Snapshots / Ephemeral VMs).
2. **Local-First & Zero Telemetry:** Работает полностью локально на вашем компьютере без облачных зависимостей и учетных записей.
3. **Кроссплатформенность:** Нативная поддержка macOS (Apple Silicon Hypervisor) и Linux (KVM).

## 🚀 3. Быстрый старт

```bash
# Установка бинарника ArcBox
cargo install arcbox

# Запуск изолированной песочницы для агента за 80 мс:
arcbox run --rm -it alpine:latest sh
```
