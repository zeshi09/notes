## 🎯 1. В чем проблема и почему 42k+ звёзд?

Современные передовые модели (Claude 3.7 / Opus, GPT-4o, Gemini 1.5/2.0) по умолчанию обучены на чрезмерно вежливый, многословный и описательный стиль взаимодействия. Когда разработчик задает конкретный технический вопрос, кодинг-агент часто выдает простыню текста:
1. **Преамбула-вступление:** *«Отличный вопрос! Давайте подумаем об этом вместе...»*
2. **Пересказ контекста:** *«В вашем auth flow есть несколько движущихся частей: мидлвара, куки, токены...»*
3. **Размазанное решение:** Решение спрятано где-то на третьем экране в середине рассуждений.
4. **Бесполезное завершение:** *«Надеюсь, это поможет! Дайте знать, если хотите копнуть глубже!»*

Для разработчика в состоянии высокой когнитивной нагрузки (или с СДВГ / синдромом дефицита внимания и гиперактивности) такой вывод превращается в **ментальную стену**:
* **Короткая рабочая память:** То, что ушло за пределы экрана, мгновенно выпадает из фокуса. Нельзя требовать «держать в голове X».
* **Трение между знанием и действием:** Знать, как исправить баг, не равно исправить баг. Работа умирает именно в зазоре между «понял» и «сделал».
* **Барьер входа:** Самый тяжелый шаг — это начать. Первое действие должно быть очевидным, крошечным и исполнимым прямо сейчас.
* **Искаженное восприятие времени:** Фразы «придется немного повозиться» и «займет пару часов» ощущаются одинаково абстрактно. Нужны конкретные минуты.
* **Дефицит дофамина:** Закопанные в текст победы не регистрируются мозгом. Прогресс должен быть наглядным.

**i-have-adhd** — это не просто инструкция «будь краток». Это строгая инженерная спецификация формата вывода, оптимизированная под мгновенный переход к действию.

## 📜 3. Десять железных правил `i-have-adhd`

В основе скилла лежит манифест из 10 правил, сформулированных в [`SKILL.md`](https://github.com/ayghri/i-have-adhd/blob/main/skills/i-have-adhd/SKILL.md):

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        10 RULES OF I-HAVE-ADHD                         │
├────┬─────────────────────────────┬─────────────────────────────────────┤
│ 1  │ Lead with the next action   │ Первая строка — это действие (bash/ │
│    │                             │ путь/сниппет), а не рассуждения.    │
├────┼─────────────────────────────┼─────────────────────────────────────┤
│ 2  │ Number multi-step tasks     │ Нумерованный список шагов. Никаких  │
│    │                             │ двойных "а затем" в одном шаге.     │
├────┼─────────────────────────────┼─────────────────────────────────────┤
│ 3  │ End with one next step      │ Финал — ОДНО конкретное действие,   │
│    │                             │ выполнимое менее чем за 2 минуты.   │
├────┼─────────────────────────────┼─────────────────────────────────────┤
│ 4  │ Suppress tangents           │ Никаких попутных советов. Сначала   │
│    │                             │ закончить задачу, сайдбары — потом. │
├────┼─────────────────────────────┼─────────────────────────────────────┤
│ 5  │ Restate state every turn    │ Напоминать статус: "Шаг 3 из 5".    │
│    │                             │ Контекст между ходами не помнится.  │
├────┼─────────────────────────────┼─────────────────────────────────────┤
│ 6  │ Specific time estimates     │ Только точные единицы: "15 минут",  │
│    │                             │ а не "займет немного времени".      │
├────┼─────────────────────────────┼─────────────────────────────────────┤
│ 7  │ Make wins visible           │ Показывать, ЧТО заработало, а не    │
│    │                             │ пересказывать процесс изменений.    │
├────┼─────────────────────────────┼─────────────────────────────────────┤
│ 8  │ Matter-of-fact errors       │ Сухой факт: ошибка, причина, фикс.  │
│    │                             │ Запрещены "Ой-ой", "Кажется сбой".  │
├────┼─────────────────────────────┼─────────────────────────────────────┤
│ 9  │ Cap lists to 5 items        │ Списки в финальном ответе — макс 5  │
│    │                             │ пунктов. Остальное скрывать.        │
├────┼─────────────────────────────┼─────────────────────────────────────┤
│ 10 │ No preamble, no closers     │ Полный бан на вежливые заполнители  │
│    │                             │ ("Great question!", "Hope helps!"). │
└────┴─────────────────────────────┴─────────────────────────────────────┘
```

### Чек-лист перед отправкой ответа агента (Pre-send check):
Перед тем как вывести сообщение пользователю, агент обязан внутренне удалить:
1. Первое предложение, если оно лишь объявляет, что агент «собирается сделать».
2. Последнее предложение, если оно спрашивает «чем еще помочь?» или пересказывает то, что только что произошло.
3. Любые фразы типа «кстати» (*by the way*).
4. Любые пустые модальные слова сомнения (*perhaps, might, could possibly*).
5. Метафоры и идиомы (*«вернуться к истокам», «на одной волне»*), заменив их буквальным действием.

## 🛡️ 4. Когда правила разрешено нарушать (Safety Overrides)

Автор скилла заложил строгие предохранители, когда прямолинейность должна уступить место безопасности или глубине:

1. **Деструктивные операции:** Если впереди опасная команда (`rm -rf`, `git push --force`, миграция БД с `DROP COLUMN`), агент **обязан запросить подтверждение**. Безопасность всегда выше краткости.
2. **Прямой запрос на объяснение:** Если пользователь явно попросил: *«Объясни подробно»* или *«Walk me through»*, агент выдает глубокий развернутый ответ, но по-прежнему без преамбул и с четкими заголовками для беглого чтения.
3. **Debug Spiral (Тупик отладки):** Если последние 3 хода подряд агент выдает «все еще не работает», он обязан **остановить генерацию кода**, вслух назвать неверное допущение и задать ровно один диагностический вопрос.
4. **Конфликт с харнесом:** Если системный промпт среды исполнения (например, Tool Broker или TCB) требует обязательного объявления тула, правила харнеса имеют абсолютный приоритет.

### Вариант 1: Claude Code CLI
```bash
# Через встроенный менеджер плагинов
claude plugin marketplace add ayghri/i-have-adhd
claude plugin install i-have-adhd@i-have-adhd
```
Активация в диалоге:
> `/i-have-adhd`  
> *(Режим остается активным до явной команды «stop adhd mode» или «normal mode»)*.

### Вариант 2: Cursor IDE
Создайте файл `.cursor/skills/i-have-adhd/SKILL.md` в корне репозитория и скопируйте туда содержимое официального манифеста.

В репозитории есть готовый скрипт `hooks/always-on.sh`, который можно подключить как пре-промпт хук к Antigravity, OpenCode, Codex или Pi CLI.
