🐍 Monty: Минималистичный и безопасный интерпретатор Python на Rust для AI-агентов

Ссылка на репозиторий: https://github.com/pydantic/monty
Организация: Pydantic (Сэмюэл Колвин / Samuel Colvin)
Звёзды GitHub: 8,200+ ★
Стек: 100% чистый Rust, Python 3.14 subset, WebAssembly, Astral ty
Назначение: Безопасное исполнение кода AI-агентов (Code Mode / Programmatic Tool Calling)
Лицензия: MIT

🎯 1. В чем главная проблема и зачем создан Monty?

Когда AI-агенту нужно выполнить цепочку действий, традиционный подход с вызовом инструментов (Tool Calling в формате JSON) работает медленно и неэффективно:

  • Агент тратит лишние токены на каждый вызов инструмента.
  • Не может выполнить простой цикл for или условие if без обращения к серверу LLM.
  • Передача промежуточных данных между 10 инструментами раздувает контекстное окно.

Решение индустрии (Anthropic, Cloudflare, Hugging Face, Pydantic) — «Code Mode» / Programmatic Tool Calling: агент сам пишет скрипт на Python, объединяющий вызовы функций, циклы и обработку данных.

Но как безопасно запустить сгенерированный LLM код?

  • Запуск на хосте: Смертельно опасно (модель может вызвать os.system("rm -rf /")).
  • Docker / микро-VM (ArcBox): Безопасно, но запуск контейнера занимает от 50 до 500 миллисекунд и требует мегабайты памяти.

Monty предлагает революционную альтернативу:
Это полноценный интерпретатор подмножества Python 3.14, написанный с нуля на Rust. Он запускается прямо внутри процесса вашего приложения со временем старта менее 1 микросекунды (<1 μs)!

💎 2. Ключевые возможности Monty

  1. Мгновенный запуск (<1 μs): В тысячи раз быстрее Docker и Firecracker. Идеально подходит для высоконагруженных агентов, выполняющих тысячи сниппетов в секунду.
  2. Безопасность на уровне архитектуры: У интерпретатора физически нет системных вызовов к Linux/macOS API. Если вы не передали функцию read_file, агент физически не сможет прочитать диск.
  3. Сериализация состояния (Snapshotting): Если агент вызвал внешнюю асинхронную функцию (например, одобрение действия человеком в Slack), Monty сериализует весь стек исполнения в бинарный массив (bytes), сохраняет в SQLite/Postgres и засыпает, освобождая ресурсы.
  4. Поддержка стандартной библиотеки: Включает безопасные реализации asyncio, json, math, re, datetime, collections, dataclasses, itertools, typing.

⚠️ 3. Ограничения (Что Monty намеренно НЕ умеет)

Monty спроектирован исключительно для выполнения кода агентов, а не для запуска продакшен-бэкендов:

  • ❌ Нет поддержки сторонних C-библиотек из PyPI (numpy, pandas, pydantic нельзя импортировать внутри Monty).
  • ❌ Нет сложного ООП (наследование классов, метаклассы и super() не поддерживаются; простые классы работают).
  • ❌ Нет доступа к хостовой сети и ФС без явных прокси-функций.

🚀 4. Как использовать в Python?

# Установка через uv или pip
uv add pydantic-monty

import asyncio
from pydantic_monty import Monty

# 1. Определяем функции, к которым агент имеет доступ
async def fetch_price(ticker: str) -> float:
    return 150.25 if ticker == "AAPL" else 42.0

# 2. Код, сгенерированный LLM
agent_code = """
price = await fetch_price("AAPL")
result = f"Цена акции AAPL: {price * 1.05:.2f} с учетом комиссии"
result
"""

# 3. Безопасное исполнение в Monty за микросекунды
monty = Monty()
result = asyncio.run(monty.eval(agent_code, host_functions={"fetch_price": fetch_price}))
print(result) # "Цена акции AAPL: 157.76 с учетом комиссии"
