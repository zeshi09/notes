## 🎯 1. Архитектурная проблема: сжигание токенов при исследовании кодовой базы

Когда кодинг-агент (**Claude Code**, **Codex**, **Cursor**, **Aider**) сталкивается с незнакомой задачей или новой библиотекой, стандартный рабочий процесс выглядит крайне расточительно:
1. **Медленное линейное чтение (File Crawling Hell):**  
   Агент начинает вызывать `view_file` или `cat` для десятков файлов подряд, пытаясь нащупать нужные интерфейсы. За 10 шагов сжигается 40,000–80,000 токенов контекста, после чего наступает забывание инструкций и деградация рассуждений.
2. **Галлюцинации API из весов модели:**  
   Если агент пытается писать код по памяти из обучающей выборки, он придумывает несуществующие методы библиотек или устаревшие сигнатуры, попадая в бесконечный цикл отладки (`Fix Loops`).
3. **Громоздкость традиционных поисковых систем:**  
   Разворачивать ради локального поиска Elasticsearch или OpenSearch означает выделить 4–8 ГБ оперативной памяти под тяжелый JVM-рантайм, что неприемлемо на машине разработчика.

**XERJ решает эту проблему через парадигму Reference Coding и единый статический бинарник на чистом Rust.**

## 🏗️ 2. Парадигма Reference Coding: экономия токенов в 2.7x–5x раз

Суть паттерна **Reference Coding**, предложенного создателями XERJ:
1. Перед написанием сложного компонента агент клонирует в локальный каталог 2–3 наиболее близких проверенных open-source репозитория.
2. XERJ выполняет мгновенное автоматическое индексирование (**Zero-Config Autoindex**) в фоне.
3. Вместо чтения файлов целиком агент делает точечные гибридные запросы к локальному XERJ по протоколу MCP, вытаскивая эталонные реализации паттернов, структуры данных и обработку ошибок.

```mermaid
flowchart TD
    subgraph ProblemArea["Традиционный подход (Без XERJ)"]
        A1["Задача агенту"] --> B1["Линейное сканирование файлов<br/>(view_file x 30 раз)"]
        B1 --> C1["Контекстное окно забито (80k+ токенов)"]
        C1 --> D1["Галлюцинации и ошибки компиляции"]
    end

    subgraph SolutionArea["Reference Coding на базе XERJ"]
        A2["Задача агенту"] --> B2["Клонирование референсных OSS репо"]
        B2 --> C2["XERJ Rust Engine: мгновенный индекс<br/>(BM25 + kNN + Граф связей)"]
        C2 --> D2["Точечный MCP-запрос точных фрагментов<br/>(Сжатие контекста в 3–5 раз)"]
        D2 --> E2["Точный компилируемый код с первой попытки"]
    end
```

> **Полевые замеры:** В контролируемом исследовании ([XERJ Case Study](https://xerj.org/case-studies/reference-coding.html)) расход выходных токенов агента сократился в **2.7 раза** при идентичном коэффициенте успешного решения задач (16/16). В повседневной разработке пользователи сообщают об экономии вплоть до **5 раз**.

## ⚙️ 3. Архитектура движка XERJ под капотом

XERJ поставляется как **один нативный бинарник на Rust** без внешних зависимостей:

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        XERJ SEARCH ARCHITECTURE                        │
│                                                                        │
│   ┌────────────────────┐ ┌────────────────────┐ ┌──────────────────┐   │
│   │    Лексический     │ │     Векторный      │ │     Графовый     │   │
│   │    индекс BM25     │ │     индекс kNN     │ │      индекс      │   │
│   │ (Точные совпадения │ │ (Семантический     │ │ (Связи файлов,   │   │
│   │  символов и путей) │ │  смысл запроса)    │ │  импорты, типы)  │   │
│   └─────────┬──────────┘ └─────────┬──────────┘ └────────┬─────────┘   │
│             │                      │                     │             │
│             └──────────────────────┼─────────────────────┘             │
│                                    ▼                                   │
│                 [Reciprocal Rank Fusion (RRF) Scorer]                  │
│                                    │                                   │
│             ┌──────────────────────┴──────────────────────┐            │
│             ▼                                             ▼            │
│    [Local MCP Protocol]                          [REST / Search API]   │
│ (Claude Code, Cursor, Codex)              (1366/1369 ES-YAML Conformance)│
└────────────────────────────────────────────────────────────────────────┘
```

1. **Тройной гибридный поиск:**
   * **BM25:** моментально находит точные имена функций, макросов, типов и путей к файлам.
   * **kNN Vector:** сопоставляет смысл формулировок задачи даже при несовпадении ключевых слов. Встроенный лексический эмбеддер работает локально и оффлайн (доступна опциональная компактная нейросеть на 90 МБ).
   * **Graph Traversal:** учитывает дерево импортов, наследование классов и иерархию модулей кодовой базы.
2. **ES-YAML Conformance (1366/1369):**
   * Движок проходит 99.8% тестов совместимости со стандартом Elasticsearch Query DSL, что позволяет использовать его как прямую замену ES без переписывания интеграций.
3. **Нативная поддержка MCP и `llms.txt`:**
   * Поставляется с готовым MCP-сервером для подключения к Claude Code, Cursor и Antigravity за одну команду: `xerj init`.
4. **Агентная память (`/__memory`):**
   * Предоставляет выделенный эндпоинт для долговременного хранения фактов, заметок и архитектурных решений агента между сессиями.

## 💻 4. Быстрый старт и интеграция

### Установка и запуск:
```bash
# Установка единого бинарника
curl -fsSL https://xerj.org/get | sh

# Запуск локального демона с хранением индекса в ./data
xerj --data-dir ./data &

# Автоматическая привязка к Claude Code / Cursor через MCP
xerj init

# Индексирование кодовой базы или референсных репозиториев
xerj autoindex ~/projects/my-app
```

### Подключение через MCP-конфиг (`~/.claude.json`):
```json
{
  "mcpServers": {
    "xerj": {
      "command": "xerj",
      "args": ["mcp", "--data-dir", "/home/user/.xerj/data"]
    }
  }
}
```

## 💡 5. Выводы для базы знаний

1. **Решение проблемы контекстного голодания:**  
   Попытка заставить агента прочитать весь проект целиком в контекст — тупиковый путь. Высокоскоростной локальный гибридный поиск на Rust с графовым анализом зависимостей становится обязательным слоем для любых сложных кодинг-задач.
2. **Reference Coding как стандартная инженерная практика:**  
   Возможность дать агенту локальный доступ к проверенным эталонным реализациям (например, исходникам ядра Linux, Tokio или React) позволяет более дешевым и быстрым моделям писать код надежнее, чем дорогие модели, работающие исключительно «из головы».
